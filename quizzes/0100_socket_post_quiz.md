## 第2章: ソケットの基礎

### Q2-1: ソケットとは何か？

**模範回答**: ネットワーク通信の端点（endpoint）。ファイルディスクリプタとして扱われ、read/write でデータを送受信できる。

**あなたの回答**:

### Q2-2: `socket()` 関数の引数を説明せよ

**模範回答**:
```c
int socket(int domain, int type, int protocol);
// domain: AF_INET (IPv4) / AF_INET6 (IPv6)
// type: SOCK_STREAM (TCP) / SOCK_DGRAM (UDP)
// protocol: 通常 0（自動選択）または getprotobyname("tcp")->p_proto
```

**あなたの回答**:

### Q2-3: TCP サーバーの処理順序を述べよ

**模範回答**:
1. `socket()` - ソケット作成
2. `bind()` - アドレス・ポートに紐付け
3. `listen()` - 接続待ち状態にする
4. `accept()` - クライアント接続を受け入れ
5. `recv()`/`send()` - データ送受信
6. `close()` - 接続終了

**あなたの回答**:

### Q2-4: `bind()` でよく使う `INADDR_ANY` の意味は？

**模範回答**: すべてのネットワークインターフェースでリッスンする。ホストに複数の IP アドレスがある場合、どれでも接続を受け付ける。

**あなたの回答**:

### Q2-5: `listen()` の backlog が小さいとどうなるか？

**模範回答**: 接続待ちキューが溢れ、新しい接続が拒否される可能性がある。ft_irc では十分大きな値（例: 128）を設定すべき。

**あなたの回答**:

### Q2-6: `accept()` 後に2つのソケット fd がある理由は？

**模範回答**:
- 元のソケット（リスニングソケット）: 新しい接続を待ち続ける
- `accept()` の戻り値（接続済みソケット）: 特定のクライアントと通信

## 第5章: ソケットプログラミング（最重要）

### Q5-1: ブロッキング I/O の問題点は？

**模範回答**: 1つのクライアントの処理中に他のクライアントを処理できない。ft_irc では複数クライアントを同時に処理する必要があるため、ブロッキング I/O は使えない。

**あなたの回答**:

### Q5-2: ft_irc で fork が禁止されている理由を推測せよ

**模範回答**:
- 学習目的: ノンブロッキング I/O と I/O 多重化を理解させるため
- 実用面: プロセス間通信が複雑になる、リソース消費が大きい

**あなたの回答**:

### Q5-3: `poll()` の基本的な使い方を説明せよ

**模範回答**:
```c
struct pollfd fds[MAX_FDS];
fds[0].fd = server_fd;
fds[0].events = POLLIN;  // 読み取り可能になったら通知

int ret = poll(fds, nfds, timeout_ms);

if (fds[0].revents & POLLIN) {
    // 読み取り可能
}
```

**あなたの回答**:

### Q5-4: `poll()` が `select()` より優れている点は？

**模範回答**:
- fd 番号に制限がない（select は FD_SETSIZE まで）
- fd_set の初期化が毎回不要
- イベントと結果が別フィールド（events/revents）で分離

**あなたの回答**:

### Q5-5: ノンブロッキングソケットで `recv()` が 0 を返したら？

**模範回答**: 接続が正常に閉じられた（相手が close した）。ソケットを閉じてクライアントを削除すべき。

**あなたの回答**:

### Q5-6: ノンブロッキングソケットで `recv()` が -1 を返したら？

**模範回答**: `errno` を確認。
- `EAGAIN` / `EWOULDBLOCK`: データがまだない（正常、後で再試行）
- それ以外: エラー

## 第6章: ソケット API の舞台裏

### Q6-1: TCP 3-way ハンドシェイクを説明せよ

**模範回答**:
1. クライアント → サーバー: SYN
2. サーバー → クライアント: SYN + ACK
3. クライアント → サーバー: ACK

この後、データ転送が可能になる。

**あなたの回答**:

### Q6-2: `send()` が成功しても、相手にデータが届いたとは限らない理由は？

**模範回答**: `send()` はデータをカーネルのバッファにコピーするだけ。実際の送信は OS が非同期で行う。

**あなたの回答**:

### Q6-3: クライアントが突然切断した場合、サーバーはどう検知するか？

**模範回答**:
- 正常切断: `recv()` が 0 を返す
- 異常切断: `recv()` が -1 を返し、`errno` がエラーを示す
- 長時間無応答: タイムアウト処理（ft_irc では必須ではないが推奨）
