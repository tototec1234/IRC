## 基本方針

- **C++標準**: C++98 のみ（`-std=c++98` でコンパイル可能であること）
- **I/O多重化**: `poll()` を使用（macOS/Linux 両対応のため）
- **リファレンスクライアント**: irssi（後述の比較参照）
- **開発環境**: M2 Mac → 完成後に校舎環境へ移植
- **Mandatory パートのみ**（Bonus は対象外）

### nc (netcat) について

**課題書 IV.3 Test example で明示的に推奨されている：**

```bash
$> nc -C 127.0.0.1 6667
com^Dman^Dd
$>
```

> ctrl+D を使用してコマンドを複数の部分に分けて送信する：'com'、次に 'man'、次に 'd\n'。
> コマンドを処理するには、まず受信したパケットを集約して再構築する必要がある。

| nc の強み | 説明 |
|-----------|------|
| 生のTCPソケット | IRCプロトコルを一切解釈しない |
| ctrl+D で部分送信 | `recv()` が複数回に分かれる状況を再現 |
| 手動でコマンド入力 | `NICK alice\r\n` を直接打てる |
| バグ発見に有効 | バッファリング実装の不備を即座に露呈 |

**評価者が nc テストを行う可能性が高い。部分データ処理の実装は必須。**

### irssi について

| irssi の強み | 説明 |
|--------------|------|
| 42学生の実績 | GitHub上の ft_irc 参考実装の多くが irssi で動作確認 |

| デバッグ容易 | CLI なのでログが取りやすい |
| macOS対応 | `brew install irssi` で即インストール |

### irssi 基本コマンド

```bash
# インストール
brew install irssi

# 接続
irssi -c 127.0.0.1 -p 6667 -w <password>

# サーバー内コマンド
/nick <nickname>
/join #channel
/msg <user> <message>
/part #channel
/quit
```

### nc 基本コマンド

```bash
# 接続（-C: CRLF を送信）
nc -C 127.0.0.1 6667

# 手動でIRCコマンドを入力
PASS mypassword
NICK alice
USER alice 0 * :Alice
JOIN #general
PRIVMSG #general :Hello!

# 部分データテスト（ctrl+D で分割送信）
PRI^DVMSG #general :te^Dst
```

## AI協働ルール

Inception と同様の Navigator/Driver モデルを採用。

| 用語 | 役割 |
|------|------|
| Driver（ドライバー） | torinoue / sohyamaz（コードを書く人） |
| Navigator（ナビゲーター） | AI（方向を示す人） |

### 実装タスクの進め方

1. **AIが解説・ヒントを出す**（概念、設計方針、確認すべきこと）
2. **AIが確認コマンドを提示** → ユーザーがターミナルで実行し結果を貼る
3. **AIが構造・ヒントを示す** → ユーザーがvim等でコーディング
4. **AIがレビュー** → 修正点を指摘
5. **ペア（torinoue/sohyamaz）で確認** → 両者が理解できること
