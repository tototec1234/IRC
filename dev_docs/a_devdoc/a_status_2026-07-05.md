### 3.1 Linux 検証 vs generatePing — どちらを専攻するか

| 観点 | Linux 検証 (#6) | generatePing 配線 (#8) |
|------|-----------------|------------------------|
| 提出 | **必須** | マンダトリ外（keepalive は加点要素） |
| 依存 | マシン待ちのみ | Issue #48（A案 vs B案）+ [ping_send_policy.md](ping_send_policy.md) |
| リスク | 移植性バグの早期発見 | 設計未決のまま実装すると手戻り |

**推奨:** **Linux 検証を専攻**する。理由:

1. 提出要件で、10 時間後が最初の実行機会なら **#2–5 は macOS で先に片付け**、マシンが使える次第 `make re && make test` と nc を回す。
2. `generatePing` は `collectTimedOutClients` だけでは PING が飛ばずタイムアウト経路が実質 dead code。**Issue #48 が決まってから** [ping_send_policy.md](ping_send_policy.md) の B案等を入れる方が手戻りが少ない。
3. 時間が Linux 検証後に余れば #8。余らなければ Issue #48 決定を待ち別 PR。
