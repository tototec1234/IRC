## 本文

127.0.0.1 の、あるポートでクライアントの接続を待ち、クライアント同士が会話できるプログラムを書け。

このプログラムは、第1引数に bind するポートを取る。

引数が無いときは、標準エラーへ `Wrong number of arguments` と書き、その直後に `\n` を書き、ステータス 1 で終了する。

接続の accept を始めるより前にシステムコールがエラーを返したときは、標準エラーへ `Fatal error` と書き、その直後に `\n` を書き、ステータス 1 で終了する。

メモリを確保できないときも、標準エラーへ `Fatal error` と書き、その直後に `\n` を書き、ステータス 1 で終了する。

プログラムはノンブロッキングであること。クライアントは受信を遅らせることがある。クライアントがこちらのメッセージを読まなくても、そのクライアントを切断してはならない。

プログラム自身に `#define` 前処理指令を書いてはならない。

待ち受けるアドレスは 127.0.0.1 だけである。

受け取る fd は、あらかじめ次の性質に設定されている。`select` を呼ぶ前に `recv` または `send` を呼ぶと、その呼び出しはブロックする。`select` を経たうえで呼べば、ブロックしない。

クライアントがサーバーへ接続したとき:

- クライアントに ID を与える。最初のクライアントの ID は 0。以後のクライアントは、最後に与えたクライアント ID に 1 を足した ID を受け取る。
- 通知文の `%d` は、この ID に置き換える。
- そのとき既にサーバーへ接続していた全クライアントへ、次を送る。`server: client %d just arrived\n`

クライアントはプログラムへメッセージを送れる。

- メッセージは印字可能文字だけである。内容の検査は不要。
- 1 つのメッセージに `\n` が複数含まれることがある。
- サーバーがメッセージを受信したら、送信者以外の全クライアントへ送り直す。各行の前に `client %d: ` を付ける。

クライアントがサーバーから切断したとき:

- そのときサーバーへ接続していた全クライアントへ、次を送る。`server: client %d just left\n`

メモリリークと fd のリークは禁止。

補助として、サーバーの冒頭と、役に立つかもしれない関数を書いた `main.c` が渡される。このファイルは禁止された関数を使っていること、最終プログラムに残してはならない記述を含んでいることがある。

テスターは、メッセージを可能な限り早く送ることを期待している。不要なバッファリングをしてはならない。

評価は通常より少し長くなり得る。

ヒント: テストには `nc` を使ってよい。

ヒント: テストには `nc` を使うべきである。

ヒント: 手元のテストでは `fcntl(fd, F_SETFL, O_NONBLOCK)` を使ってよい。提出するプログラムは `select` を使い、`EAGAIN` を調べてはならない（`man 2 send`）。

## 文字列（テスターが一致を見る箇所）

| 状況 | 出力先 | バイト列 |
|------|--------|----------|
| 引数が無い | 標準エラー | `Wrong number of arguments\n` |
| accept 前のシステムコール失敗、またはメモリ確保失敗 | 標準エラー | `Fatal error\n` |
| 終了ステータス | — | `1` |
| ID `N` が接続した | 既に接続していたクライアントのソケット | `server: client N just arrived\n` |
| ID `N` の 1 行 | 送信者以外のソケット | `client N: ` の直後にその行 |
| ID `N` が切断した | 接続していた他クライアントのソケット | `server: client N just left\n` |

`client N: ` のあとには、原文どおりスペースが 1 つある。行の `\n` は残す。例として、ID 0 が `hello\n` を送ると、他クライアントへは `client 0: hello\n` が届く。

## 訳を実装の言葉に固定した箇所

課題文の英文が短いので、実装で使う意味をここに固定する。

1. **ID** は fd 番号ではない。接続のたびに 1 ずつ増える。最初は 0。切断した ID を空き番号として再発行する、とは書いていない。次の接続は、最後に発行した ID の次である。
2. **到着通知の宛先** は「既に接続していたクライアント」である。今 accept した本人には送らない。誰も居なければ、通知は 0 通である。
3. **会話の宛先** は送信者以外の全クライアントである。1 回の受信に `\n` が 2 つあれば、接頭辞付きの行が 2 本になる。
4. **切断通知の宛先** は、残って接続しているクライアントである。切断した本人の fd へは送らない。
5. **`select` がゲートである。** writable と分かる前の `send`、readable と分かる前の `recv` はブロックし得る。提出コードに `fcntl` は無い（許可関数一覧に無い）。`EAGAIN` は見ない。`send` が要求より短いバイト数を返したら、残りは保持して、次にその fd が writable になったときに送る。
6. **遅いクライアント** は、送信残りがあっても fd を開いたままにする。
7. **不要なバッファリングをしない** とは、揃った行を、書ける相手に対して遅らせずに送ることである。`\n` がまだ無い受信バイトと、writable になる前の送信残りは、課題が要求している保持である。
8. **メモリ確保の失敗** は、accept を始めたあとでも `Fatal error` で終了する。原文のこの文は「accept より前」に限定されていない。
9. **accept を始めたあとのシステムコールエラー** について、サーバー全体を `Fatal error` で落とすとは書いていない。`recv` が 0 以下のときは、そのクライアントの切断として扱う。

## 課題文に無いこと

段階の実装に入るときに、毎回ここへ戻る。

- 引数が 2 つ以上ある場合。原文が指定しているのは「引数が無い」場合である。
- ポート文字列が数値でない場合。
- `\n` の無い受信途中のバイトを、切断時に配信するか。
- 同じ `select` の戻りで、複数の fd をどの順に処理するか。
- `send` が 0 未満を返したとき、その 1 クライアントだけを切断するか。
