「読まないクライアント」が通ったことは、`flush_client` が `send` の戻り値 `n < len` のときに残りを `g_wbuf[fd]` へ移し、次に writable になってから送る実装が効いている証拠である。[課題文 和訳](../mini_serv_ja.md) の固定事項 5・6 に対応する。


### 事故 1: `bind` 成功時に `fatal()` を呼んでいた

デバッグ用 `printf` を消すとき、`else` の中身が空になるのを避けようとして `fatal()` を置いてしまった。

```c
	if (bind(...) != 0) {
		// printf("socket bind failed...\n");
		fatal();
	} else
		fatal();                 /* ← 成功しても落ちる */
```

`Socket successfully created..` の次が必ず `Fatal error` になり、ポート 8082 でも 8083 でも同じ症状が出た。ポートの枯渇や `TIME_WAIT` を疑ったが、原因はこれだった。**`else` の中身が無くなったら `else` ごと消す。**正しい形は次のとおり。

```c
	if (bind(...) != 0)
		fatal();
```

教訓: 「ポートが使えない」ように見える症状でも、先に自分のコードの分岐を疑う。`lsof` や `ss` を叩く前に、`bind` の戻り値と分岐を目で追ったほうが早かった。


### 事故 2: `nc` は EOF でも接続を切らない

`printf 'a\nb\nc' | nc 127.0.0.1 8081` を実行したあと、次のコマンドが動かなかった。標準入力が EOF になっても netcat-openbsd はサーバーからの受信を待ち続けるため、`nc` が前景に居座り、次に打ったコマンドはターミナルの入力バッファに溜まったままだった（プロンプトが出ていないのが手がかり）。`server: client 3 just left` がどこにも出ていないことが裏付けになった。

**対策: パイプで流すテストでは `-q 0` を付ける。**

```sh
printf 'a\nb\nc' | nc -q 0 127.0.0.1 8081
```

`-q 0` は標準入力が EOF になった 0 秒後に `nc` を終了させる。FIN だけ送る `-N` でもよい。Mac では毎回 Ctrl+C で切っていたため気づかなかっただけで、挙動は同じ。


### valgrind の「残り 2 ブロック」の正体

`still reachable` が 2 件出たが、どちらも直す対象ではない。


| ブロック                                     | 正体                                                                                                                 |
| ---------------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| 1,024 バイト（`printf` → `_IO_file_doallocate`） | glibc が `printf` のために確保した stdio のバッファ。自分の確保ではない。デバッグ `printf` を消せば消える                                                |
| 1 バイト（`extract_message` の `calloc`）        | `g_rbuf[fd]`。最後の行を切り出したあとの残り（空文字列の `'\0'` 1 バイト）。クライアントが繋がったままサーバーを Ctrl+C したので `handle_client` の `free` を通らずに終わっただけ |

`still reachable` は「終了時点でまだポインタが指している」であり、`lost` ではない。クライアントを全部切ってからサーバーを落とせば 0 になる。見るべき行は `definitely lost` である。


### `mini_serv.c` 最終レビュー（13:50）

課題文の要求に反する欠陥は見つからなかった。`#define` は無く、デバッグ `printf` も削除済み。

**試験で白紙から書くときに落としやすい箇所（この版では正しく書けている）:**

1. `accept_client` は `FD_SET(connfd, &g_active)` のあとに `send_all(connfd, msg)`。`except` に本人を渡すので、到着通知が本人へ行かない。
2. 切断処理の順番が `FD_CLR` → `close` → `send_all(fd, msg)`。先に `FD_CLR` するので `just left` が本人へ行かない。
3. 書き込みの判定が `FD_ISSET(fd, &wfds) && FD_ISSET(fd, &g_active)`。同じ `select` の戻りの中で切断された fd に `flush_client` しない。
4. `wfds` は毎回 `FD_ZERO` して `g_wbuf[fd] != NULL` の fd だけ立てる。全 fd を立てると `select` が常に返って回り続ける。
5. `extract_message` は `(*msg)[i + 1] = 0` なので `\n` を残す。
6. `recv(fd, buf, sizeof(buf) - 1, 0)` と `buf[n] = '\0'`。終端の 1 バイトを残す。

**把握しておく点（試験の採点では問題にならない）:**


| 点                                | 内容                                                                         |
| -------------------------------- | -------------------------------------------------------------------------- |
| `htonl` / `htons`                | 許可関数一覧に無い。慣例として通っているが、一覧に照らすとグレー                                           |
| `fd_set` の上限                     | `FD_SETSIZE` は 1024。`g_ids[65536]` などの配列サイズと一致していない。fd が 1024 以上になると未定義動作   |
| `#include <sys/select.h>` が無い     | `sys/socket.h` 経由で入るので Linux・macOS 両方で通る。明示したほうが安全                         |
| `str_join` が O(n²)               | 毎回バッファ全体をコピーする。読まないクライアントへ大量に送ると遅いが、切断はしないので要求は満たす                        |
| `fatal()` は listen fd しか閉じない      | クライアント fd と `g_rbuf` / `g_wbuf` は片づけない。直後に `exit` するので実害なし                 |
