## 次のチャットへの引き継ぎ

次のチャットは、このファイルのこの節から始める。会話の履歴は引き継がれない。

**コード:** [mini_serv.c](../mini_serv.c)。段階 7 まで書いてあり、Mac では上の到達点 2 まで確認済み。

**校舎でやること（着いたらすぐ）:**

1. `mini_serv.c` を Linux に置く（このコミットを `git pull` する）。
2. `gcc -Wall -Wextra -Werror mini_serv.c -o mini_serv` でビルドする。
3. `nc` 3 本で arrived、行、left をもう一度確かめる。ポートが `bind` に失敗したら、番号を変える（`SO_REUSEADDR` は許可関数に無い）。
4. 読まないクライアント: 1 本を Ctrl+Z で止め、別の `nc` から大量の行を流す。サーバーが止まらないこと、止めたクライアントを `fg` したあとメッセージが届くことを確かめる。手順は [学習プラン](../mini_serv_study_plan.md) の 3.7。
5. valgrind で、接続と切断のあとにリークが無いことを確かめる。
6. 14:15 には打ち切って昼食。15:00 から試験。

**12:29 に直した 2 か所（再発させない）:**

- `main` のループで、読める fd の判定に `!` を付けていた。`FD_ISSET(fd, &rfds)` が正しい。`!` があると、読めない fd に `recv` して止まる。
- 送信の判定を `FD_ISSET(fd, &rfds)` にしていた。`FD_ISSET(fd, &g_active)` が正しい。`rfds` のままだと、読める fd にしか送らない。

**Mac で通した確認:**

- 引数なし: 標準エラーに `Wrong number of arguments\n`、終了 1。
- 使用中ポート: 標準エラーに `Fatal error\n` の 12 バイト、終了 1。
- `nc` 2 本: 先に繋いだ側だけに `server: client 1 just arrived`。
- `nc` 3 本で 1 本を切る: 残りの 2 本に `just left`。次の接続は ID 3。
- `printf 'a\nb\nc' | nc`: `a` と `b` だけ届く。`c` は届かない。
- `(printf 'hel'; sleep 1; printf 'lo\n') | nc`: `client N: hello` が 1 行で届く。
